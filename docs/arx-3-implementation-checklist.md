# ARX 3 implementation checklist

This checklist normalizes the ARX 3 desktop specification as literal Points 1 through 27. It is updated after each implementation stage. A point is not marked `TESTED` merely because a neighboring feature exists.

Allowed states: `NOT STARTED`, `IN PROGRESS`, `IMPLEMENTED`, `TESTED`, `PARTIALLY IMPLEMENTED`, and `BLOCKED WITH DOCUMENTED REASON`.

| Point | State | Exact requirement | Existing ARX components involved | Minimum correct change and verification | Current limitation |
|---:|---|---|---|---|---|
| 1 | TESTED | Inspect the repository, desktop surfaces, missing interactions, and packaging before editing. | `src/arx/desktop`, `scripts`, `packaging`, `.github`, `tests` | Audited Tkinter/ttk widgets, result trees, text/report views, dialogs, worker thread, PyInstaller release, and absent CI/installer; baseline was 105 passing tests on Windows/Python 3.10. | None. |
| 2 | IN PROGRESS | Give meaningful visible information the Windows actions users reasonably expect. | `desktop/app.py`, `desktop/widgets.py` | Add reusable selectable/copyable/searchable/saveable text and actionable result/path surfaces; integration tests will verify exposed actions. | GUI integration is pending. |
| 3 | NOT STARTED | Add representative context-sensitive right-click menus for text, JSON, results, paths, and errors. | All desktop `Text` and `Treeview` widgets, report/error windows | Bind focused menus whose commands depend on the selected object and existing path state. | Pending reusable menu foundation. |
| 4 | NOT STARTED | Support Ctrl+C, Ctrl+A, Ctrl+F, Ctrl+S, Enter, Esc, and sensible Tab navigation. | Text/report widgets, trees, dialogs, application menu | Centralize standard bindings and route commands to the focused control/current report. | Pending reusable bindings. |
| 5 | NOT STARTED | Make meaningful scan, status, error, JSON, path, explanation, and project text selectable. | Disabled text panels, labels, trees | Keep report text read-only but selection-enabled; expose label information in selectable detail surfaces. | Pending GUI integration. |
| 6 | NOT STARTED | Add safe natural double-click behavior for paths/findings/details. | Result trees and evidence selection | Double-click rows for details and existing paths for user-requested open/reveal actions only. | Pending GUI integration. |
| 7 | NOT STARTED | Make colored result rows selectable, focusable, copyable, inspectable, and textual. | All ttk `Treeview` result surfaces and `StatusBadge` | Preserve textual statuses/tags and add row selection, keyboard focus, detail, copy, and contextual actions. | Pending GUI integration. |
| 8 | NOT STARTED | Provide clear responsive operation state, conflicting-control disable/restore, completion/failure/cancel feedback. | `ARXDesktopApp._run/_poll`, worker queue, progress bar | Generalize bounded background tasks, busy controls, cancellation tokens, and status messages without blocking Tk. | Pending desktop task runner changes. |
| 9 | NOT STARTED | Use natural Windows dialogs, filters, and session last-directory behavior. | Existing `filedialog` calls and report export | Centralize dialog options, remember only an in-memory last directory, and support JSON/text/all-file filters. | Pending GUI integration. |

| 25 | IN PROGRESS | Implement incrementally with small reusable changes, focused tests, minimal disruption, and preserved APIs/semantics. | Entire change set | Run focused tests and inspect diffs after each major stage; avoid unrelated formatting/dependencies. | Continues until final verification. |
| 26 | NOT STARTED | Produce final engineering report covering problems, changes, files, tests, manual verification, limitations, and security. | Final response and this checklist | Generate evidence-backed report after the full suite/security audit. | Final stage only. |
| 27 | NOT STARTED | Add optional redacted AI/Codex/web investigation, context intelligence, consent, cancellation, advisory separation, CI/CodeQL, and boundary tests. | New provider/context/web modules, desktop context menus/panel, `.github/workflows` | Use Responses API and read-only ephemeral `codex exec`; explicit preview/consent; safe browser queries; advisory-only UI; Windows/Linux CI and CodeQL. | No API key is configured, so live OpenAI verification will remain explicit unless one is later provided. |
